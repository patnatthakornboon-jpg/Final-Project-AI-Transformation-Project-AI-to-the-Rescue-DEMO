# AI Event & Venue Space Planner

โปรเจกต์วิชา **IT232 Artificial Intelligence for Information Technology** — *AI Transformation Project: AI to the Rescue* (หัวข้อที่ 30)

บอกโจทย์ของงานเป็นภาษาธรรมดา (เช่น "งานสัมมนา 100 คน มีเวทีและซุ้มอาหาร งบ 5 หมื่นบาท") แล้วระบบจะให้

- ผังพื้นที่แบบ schematic ขนาดสัดส่วนตามพื้นที่ที่คำนวณ
- พื้นที่ที่ต้องใช้ และขนาดสถานที่ขั้นต่ำที่ควรหา
- รายการอุปกรณ์ที่ต้องจัดเตรียม (Checklist) พร้อมจำนวนและราคาโดยประมาณ ดาวน์โหลดเป็น CSV ได้
- ตารางเทียบ 3 ระดับงบ (ประหยัด / มาตรฐาน / พรีเมียม) และคำเตือนเมื่อเกินงบ
- คำแนะนำเรื่องความเสี่ยงและทางเลือกประหยัดงบ

## ปัญหาและแนวคิด

การวางผังงานด้วยมือต้องเปิดตารางพื้นที่ต่อคน คำนวณจำนวนโต๊ะ เก้าอี้ และอุปกรณ์ แล้วเทียบกับงบ ซึ่งช้าและพลาดง่าย
ระบบนี้แบ่งงานให้เหมาะกับจุดแข็งของแต่ละส่วน

| ขั้นตอน | ทำโดย | เหตุผล |
|---|---|---|
| อ่านโจทย์ภาษาไทย/อังกฤษ -> ข้อกำหนดแบบมีโครงสร้าง | LLM (Gemini/OpenAI) ที่ปรับด้วย Prompt Engineering (few-shot) หรือ rule-based เมื่อไม่มี key | ภาษาธรรมชาติคือจุดแข็งของ LLM |
| คำนวณพื้นที่ จำนวนอุปกรณ์ ราคา | rule engine จากไฟล์ `*.json` | ตัวเลขต้องถูกต้องและตรวจสอบย้อนกลับได้ ไม่ให้ AI เดา |
| เขียนคำแนะนำ | LLM จากตัวเลขที่คำนวณแล้วเท่านั้น (ห้ามแต่งตัวเลขใหม่) | อธิบายเป็นภาษามนุษย์ |

ผลจาก LLM ผ่านตัวกรอง (`sanitize_requirements`) ทุกครั้ง ค่าที่ไม่อยู่ใน data ถูกทิ้ง และถ้าเรียก LLM ไม่ได้ระบบจะ fallback อัตโนมัติและแจ้งผู้ใช้

## Workflow

```
ข้อความโจทย์ ──> [LLM / rule-based parser] ──> ข้อกำหนด (JSON) ──> ผู้ใช้ตรวจ/แก้ในฟอร์ม
                                                                         │
 ผังพื้นที่ + Checklist + เทียบงบ <── [Rule Engine + *.json] <──────┘
                                                │
                                   [LLM] เขียนคำแนะนำจากตัวเลขจริง
```

## วิธีใช้งาน

### 1) เว็บ (GitHub Pages)

1. อัปโหลดไฟล์ทั้งหมดขึ้น GitHub ที่ระดับบนสุดของรีโป (ไม่ต้องสร้างโฟลเดอร์)
2. ไปที่ **Settings -> Pages -> Build and deployment -> Source: Deploy from a branch** เลือก branch `main` โฟลเดอร์ `/ (root)`
3. รอ 1-2 นาที จะได้ลิงก์ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

เปิดในเครื่องก็ได้โดยดับเบิลคลิก `index.html` (ไม่ต้องมีเซิร์ฟเวอร์)

ถ้าต้องการให้ AI (Gemini) ทำงาน ให้เปิดกล่อง "ใช้ AI" ในหน้าเว็บแล้ววาง API key key จะถูกใช้ส่งตรงจากเบราว์เซอร์ไปยัง Google เท่านั้น
ไม่ถูกบันทึก และ **ห้ามใส่ key ลงในไฟล์ในรีโป**

**เลือกโมเดลอัตโนมัติ:** ถ้าเว้นช่อง "ชื่อโมเดล" ว่าง ระบบเริ่มที่ `gemini-3.8-flash` และถ้า Google ตอบว่าโมเดลนี้ใช้กับบัญชีไม่ได้
(404 / not found / not supported / 403) ระบบจะลองโมเดล flash ที่บัญชีนั้นมีอีกไม่เกิน 2 รุ่น แล้วจำรุ่นที่ใช้ได้ไว้ในหน่วยความจำ
กรณีอื่น (key ผิด 400, โควตา 429, เครือข่าย) ไม่สลับโมเดล และแสดงข้อความผิดพลาดเดิมจาก Google ถ้าระบุชื่อโมเดลเอง ระบบจะใช้ชื่อนั้นเสมอ
ถ้า AI ใช้ไม่ได้ ระบบทำงานต่อด้วยโหมด rule-based และแจ้งผู้ใช้เสมอ

**ฟอร์มอัปเดตเองขณะพิมพ์:** พิมพ์โจทย์เสร็จรอประมาณครึ่งวินาที ตัวอ่านโจทย์แบบ rule-based จะกรอกฟอร์มและแสดงผลให้เอง (Streamlit: กด Ctrl+Enter หรือคลิกนอกช่อง) ส่วนการให้ AI อ่านต้องกดปุ่ม "อ่านโจทย์แล้วกรอกฟอร์ม" เพื่อไม่เรียก AI ทุกตัวอักษร

**เริ่มต้นแบบว่าง:** เปิดหน้าเว็บมาจะไม่มีข้อความเติมไว้ พิมพ์โจทย์หรือกดตัวอย่าง (หรือปรับฟอร์ม) แล้วผลจึงปรากฏ ไม่ต้องลบของเดิม

## แก้ปัญหาเมื่อเรียก AI ไม่สำเร็จ

กดปุ่ม **ทดสอบการเชื่อมต่อ AI** (เว็บ: ในกล่อง "ใช้ AI" / Streamlit: แถบด้านข้าง) ระบบจะตรวจ key รายการโมเดลที่บัญชีใช้ได้ และเรียกทดสอบ 1 ครั้ง
แล้วแสดง **เหตุผลจริงจาก Google** (ไม่มี key ปนในข้อความ) ระหว่างนี้ระบบยังทำงานต่อด้วยโหมด rule-based เสมอ

| ข้อความที่เห็น | ความหมาย | วิธีแก้ |
|---|---|---|
| `HTTP 400 INVALID_ARGUMENT API key not valid` | key ผิด วางไม่ครบ หรือมีตัวอักษรแปลกปน | สร้าง key ใหม่ที่ Google AI Studio แล้ววางใหม่ทั้งหมด |
| `HTTP 403 PERMISSION_DENIED Your project has been denied access` | ฝั่ง Google จำกัดสิทธิ์ของโปรเจกต์/บัญชีที่สร้าง key ไม่ใช่ข้อผิดพลาดของโปรเจกต์นี้ | ลองสร้าง key ด้วยบัญชี Google ส่วนตัว (Gmail) ยืนยันอายุและเบอร์โทรในบัญชี Google หรือดูหัวข้อ 403 ที่ discuss.ai.google.dev |
| `ไม่พบโมเดล '...' ในบัญชีนี้ — ลองใช้: ...` | ชื่อโมเดลที่ตั้งไว้ใช้ไม่ได้กับบัญชีนี้ | คัดลอกชื่อที่ระบบแนะนำไปใส่ในช่อง "ชื่อโมเดล" |
| `HTTP 429` | โควตาฟรีหมดชั่วคราว | รอสักครู่แล้วลองใหม่ |
| `เชื่อมต่อไม่ได้` | ไม่มีอินเทอร์เน็ต หรือเครือข่ายบล็อก Google | ลองเครือข่ายอื่น |

## การทดสอบและวัดผล (System Validation)

```bash
python validate_data.py              # ตรวจ data (schema, id ซ้ำ, การอ้างอิงข้ามไฟล์, ช่วงตัวเลข)
python -m unittest discover -v    # unit tests (43 รายการ)
node test_ai_js.js                   # ทดสอบการเรียก AI ฝั่ง JS (11 เคส ไม่ใช้เน็ต)
python compare_js.py                 # JS ต้องให้ผลตรงกับ Python ทุกสถานการณ์ (1,000+ แผน, 1,500+ ข้อความสุ่ม, ป้ายชื่อในผัง)
python evaluate.py --write       # วัดความแม่นยำ และเขียน validation_report.md
python evaluate.py --llm --write   # วัดโหมด LLM ด้วย (ต้องมี API key)
```

ผลล่าสุดของโหมด rule-based กับโจทย์ 26 ข้อความ: ถูกครบทุกฟิลด์ 24/26 เคส (ความแม่นยำรายฟิลด์รวม 97%)
2 เคสที่ผิดตั้งใจเก็บไว้เป็นเคสยาก เพื่อให้เห็นเหตุผลที่ต้องมีโหมด LLM ดูรายละเอียดใน `validation_report.md`

**ตัวชี้วัดที่ยังต้องเก็บจากผู้ใช้จริง:** เวลาที่ลดลง (%) และ Feedback จากกลุ่มตัวอย่าง รายงานมีส่วนเตรียมไว้แล้ว
ให้จับเวลาผู้ทดสอบ 3-5 คน วางแผนด้วยมือเทียบกับใช้เครื่องมือนี้ แล้วรัน
`python evaluate.py --manual-minutes <เฉลี่ยด้วยมือ> --tool-minutes <เฉลี่ยด้วยเครื่องมือ> --write`

## ข้อจำกัด

- ราคาอุปกรณ์และพื้นที่ต่อคนเป็นค่าประมาณทั่วไปเพื่อการวางแผนเบื้องต้น ควรตรวจกับผู้ให้บริการและข้อกำหนดของสถานที่จริง
- ผังพื้นที่เป็น schematic ไม่ใช่แบบก่อสร้าง และสมมติห้องสี่เหลี่ยมอัตราส่วน 3:2
- ข้อมูลความปลอดภัย (ทางออก ห้องน้ำ) เป็นแนวทางคร่าว ๆ ไม่แทนข้อกำหนดตามกฎหมายอาคาร
- ตัวอ่านโจทย์แบบ rule-based พลาดกับสำนวนที่ไม่มีคำสำคัญ (เช่น "meetup") โหมด LLM ช่วยในจุดนี้
- งานนิทรรศการใช้ layout แบบยืน (cocktail) เป็นตัวแทนผู้เข้าชม จึงมีโต๊ะค็อกเทลในรายการด้วย ควรตัดออกเองหากไม่จำเป็น
- ในห้องใหญ่ โซนเล็กมาก (เช่น มุมถ่ายภาพ 9 ตร.ม. ในงาน 1,000 คน) จะเล็กเกินกว่าจะใส่ป้ายชื่อในผัง ใช้ชี้เมาส์ดู tooltip หรือดูตารางโซนใต้ผัง
- ผลการทดสอบความแม่นยำของโหมด LLM ยังไม่ได้วัดจริง (ต้องใช้ API key) มีเฉพาะผลโหมด rule-based
